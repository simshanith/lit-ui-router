GENERAL NOTES

Method — one census, cited throughout. Every count on this plate comes from a fresh 2026-08-17 census of the repo at HEAD: the 11 workflow files, all 17 turbo.json files, .config/mise/** and both member mise.toml files read directly, cross-checked against mise tasks ls --all and bare turbo run ci --dry=json. Three figures on the sheet-3 inset had drifted and were corrected at rev A: 36→37 workflow call sites, 51→48 repo-defined mise tasks (the 51 had mixed in four user-global rtk:* tasks), and 483→501 ci graph nodes after the lit dedupe — the phantom share held at 68.5%.

Rev B — census refresh, 2026-08-31. The plate was re-measured from the same sources at HEAD, and the finding it exists to make survived intact: the mise machine did not move a single task. 48 tasks in the same four homes, 2 depends declarations, 21 $usage_* specs, 37 workflow call sites across the same 8 of 11 workflows, the same 7 ★ / 7 ↩ disjoint sets, the same 6 re-entrant ports, the same one dead task. Only turbo's graph grew, and only because the workspace did: three new members — @tools/lint-elements, @tools/warn-lanes (#639) and @tools/eslint-ts-parser — take the ci graph from 501 nodes / 158 real to 535 / 165, edges 1,294 → 1,375, real→real 116 → 117, and the phantom share from 68.5% to 69.2%. ci:main now stands at 567 nodes / 170 real. The turbo definitions are unchanged at 91 across the same 17 files: every new node is fan-out, not authorship. Two other figures were corrected in passing — the repo holds 12 cache:false definitions, not 11 (7 at root, 5 in member files; still zero reachable from ci) — and four turbo.json line citations moved as //#lint:elements landed above them. A new root lint lane, //#lint:elements, joins the lint fan but is not a re-entrant port: it runs a node bin, not mise run.

The star fitting: turbo caches mise. Six root //# scripts in the ci graph have mise run … as their literal command, and their turbo inputs explicitly hash .config/mise/tasks/* and .config/mise/mise.lock (turbo.json:224-228, 241-247, 252-258). That is the whole trade drawn as one gasket on the return duct: mise owns the tool versions (taplo, rumdl, shellcheck, actionlint, zizmor — none installable by node), turbo owns the cache, and the gasket hashes one machine against the other, so a taplo pin bump invalidates exactly the taplo lane and nothing else.

A DAG in a loop costume. The circuit workflow → mise → turbo → mise looks re-entrant, but the 48 tasks partition cleanly: the seven that shell turbo (★ — ci, ci_main, build, codecov_bundle, dts_backtest_matrix, check_pack, published_diff) are reachable only from workflows and humans, while the seven turbo re-enters (↩ — the lint and format tasks) only exec pinned binaries or file tasks. No edge leads from the second set back to the first. The deepest chain is six hops and runs on every PR, four tool lanes in parallel: workflow YAML → mise run ci → turbo run ci → //#lint:toml → mise run lint_toml → the taplo file task → the pinned binary.

Three service doors, all deliberate. deflake-e2e.yml:73 runs bare turbo run build --filter=… — over the umbrella, though mise still supplies the PATH; deflake-e2e.yml:87 runs the flake attempts through pnpm outside turbo, because a cached test task would replay attempt 1’s logs; and the production docs deploy never sees mise at all — Cloudflare Workers Builds bootstraps with npx pnpm@11.21.0 then npx turbo docs#build (tools/workers-builds/cloudflare-build.sh:16-19), because the hosted image’s corepack shim cannot materialize pnpm 12. The doors are drawn red and hatched because each one gives up something the machines provide — and each was opened on purpose.

Two curiosities the census surfaced. One task in the whole machine is dead: //tools/build_and_test:playwright_deps (mise.toml:72-76) has no caller anywhere, superseded by playwright_deps_engines. And one umbrella exists twice: mise lint_workflows (a 4-leg depends, config.toml:131-135) and turbo //#lint:workflows (a virtual with node, turbo.json:211-221) are the same shape maintained by hand in both schedulers — the one place the two machines duplicate rather than delegate. The phantom shroud around turbo’s core — 370 of 535 nodes that exist only to carry hashes — is drawn as wall thickness here; sheet 12 punches it hole by hole.
