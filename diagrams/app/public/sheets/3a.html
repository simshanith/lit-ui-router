The star fitting: turbo caches mise. Six root //# scripts in the ci graph have mise run … as their literal command, and their turbo inputs explicitly hash .config/mise/tasks/* and .config/mise/mise.lock (turbo.json:264-268, 281-287, 292-298); a seventh port, @tools/release#check:release-closure, re-enters from a member script and hashes config.toml the same way (tools/release/turbo.json:39-50). That is the whole trade drawn as one gasket on the return duct: mise owns the tool versions (taplo, rumdl, shellcheck, actionlint, zizmor — none installable by node), turbo owns the cache, and the gasket hashes one machine against the other, so a taplo pin bump invalidates exactly the taplo lane and nothing else.

A DAG in a loop costume. The circuit workflow → mise → turbo → mise looks re-entrant, but the 51 tasks partition cleanly: the seven that shell turbo (★ — ci, ci_main, build, codecov_bundle, dts_backtest_matrix, check_pack, published_diff) are reachable only from workflows and humans, while the eight turbo re-enters (↩ — the lint and format tasks, and check_release_closure) only exec pinned binaries, file tasks or a manifest reader. No edge leads from the second set back to the first. The deepest chain is six hops and runs on every PR, four tool lanes in parallel: workflow YAML → mise run ci → turbo run ci → //#lint:toml → mise run lint_toml → the taplo file task → the pinned binary.

Three service doors, all deliberate. deflake-e2e.yml:73 runs bare turbo run build --filter=… — over the umbrella, though mise still supplies the PATH; deflake-e2e.yml:87 runs the flake attempts through pnpm outside turbo, because a cached test task would replay attempt 1’s logs; and the production docs deploy never sees mise at all — Cloudflare Workers Builds clears corepack’s shims and installs pnpm@12.2.1 globally through npm before npx turbo docs#build (tools/workers-builds/cloudflare-build.sh:26-38), because the hosted image’s corepack shim cannot materialize pnpm 12. The doors are drawn red and hatched because each one gives up something the machines provide — and each was opened on purpose.

Two curiosities the census surfaced. One task in the whole machine is dead: //tools/build_and_test:playwright_deps (mise.toml:72-76) has no caller anywhere, superseded by playwright_deps_engines. And one umbrella exists twice: mise lint_workflows (a 4-leg depends, config.toml:139-143) and turbo //#lint:workflows (a virtual with node, turbo.json:251-261) are the same shape maintained by hand in both schedulers — the one place the two machines duplicate rather than delegate. The phantom shroud around turbo’s core — 465 of 660 nodes that exist only to carry hashes — is drawn as wall thickness here; sheet 12 punches it hole by hole.
