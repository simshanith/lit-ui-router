Sheet 10 is the unified view — one real app's bundle with all of these mixed by the bundler; this sheet cuts the same machinery by published package and entry point. The quarters don't sum and shouldn't: doors overlap (./pure is . minus registration), which is exactly what the split view exists to show.

The twin towers are one building with two doors. . and ./pure differ by 90 gzipped bytes — the whole cost of custom-element registration. The register economics run the other way: the two one-element doors sum to 3,534 gz while the umbrella ./register is 2,482, because each element door carries the shared element core with it. Take the umbrella or one element door; taking two per-element doors ships the core twice.

The server is a storefront, not a tower. Eight doors: an index at 4,965 gz — rev A caught it within 12 bytes of lit-ui-router's flagship, a coincidence #590 promptly broke and the summer has widened to 642 — redirect and matcher wings, and four framework adapters — hono, fetch, vite, connect — packed within 72 bytes of one another: thin skins over one core. ./simulate, the test double, is 283 bytes. All eight of these doors reprobe byte-identical against rev B.

Plugins price like footnotes. The entire mobx reactivity layer enters at 650 gz and the navigation-location plugin at 670 — each cheaper than the gap between ./register and its two element doors. The expensive thing in this family is never the adapter; it is the state machine they all defer to, and that machine (sheet 10's @uirouter/core) is external here by design.

The sixteenth door is not a door a browser opens. eslint-plugin-lit-ui-router (#676) is the family's fifth published package and the first non-runtime one, so its quarter is drawn but its number means something different: 9,253 minified, 3,194 gz is what a lint host loads, once, at author time. It is priced here because the probe prices every published entry without exception — the honest thing for a ledger — and it is worth knowing that the plugin costs 57% of the flagship to a tool that already has Node's whole module graph resident. Nothing in it ever reaches a bundle: it peers ESLint and oxlint, never @uirouter/core (sheet 2 leaves it off the plate for the same reason).

Why both views exist. The split view is the seller's ledger — what each door costs at the threshold. The unified view is the buyer's receipt — what one app's bundler actually made of them (it paid 4,654 of the flagship's 5,607). Codecov tracks the ledger per commit; sheet 10 audits the receipt.
